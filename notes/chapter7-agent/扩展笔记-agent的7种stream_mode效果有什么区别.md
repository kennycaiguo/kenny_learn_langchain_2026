在基于 **LangGraph** (LangChain 旗下的 Agent 编排框架) 构建 AI Agent 时，提供的 **7 种 `stream_mode`** 主要用于控制流式输出的**数据粒度**和**应用场景**。 

它们的区别可以总结为：**决定了你在 Agent 执行过程中，能以什么样的“视角”和“细粒度”拿到数据**。 

7 种 `stream_mode` 效果对比表

| 模式 (`stream_mode`) | 返回内容                                               | 数据粒度             | 典型应用场景                                         |
| -------------------- | ------------------------------------------------------ | -------------------- | ---------------------------------------------------- |
| **`messages`**       | LLM 生成的 **Token（字词块）** 及元数据                | 🌟 **最细 (Token级)** | 前端对话框的 **“打字机”** 逐字渲染效果               |
| **`updates`**        | 每个节点执行完后的 **状态增量 (Deltas)**               | 中等                 | 监控 Agent 流程（如“正在调用工具X”、“工具返回结果”） |
| **`values`**         | 每个节点执行完后的 **完整状态快照**                    | 最粗                 | 分析状态机的演进轨迹、需要展示全局上下文的看板       |
| **`custom`**         | 开发者在节点内部使用 `writer` 自定义的特定数据         | 自定义               | 耗时任务的**进度条提示**（如“已处理 30%”）           |
| **`tasks`**          | 节点/任务的**生命周期事件**（开始、结束、错误）        | 中等                 | 执行流的结构化日志审计、节点级的错误捕获             |
| **`checkpoints`**    | 状态持久化时的 **检查点事件**（与 `get_state()` 一致） | 中等                 | 长时间运行任务的容灾恢复、实现“时间旅行”回溯调试     |
| **`debug`**          | 包含以上绝大部分内容的 **全量调试流**                  | 💥 **最全**           | 本地开发排错、深度观测 Agent 行为                    |

详解每种模式的效果与差异

1. `messages`（消息/Token流）—— **打字机效果专用**

- **效果：** 只要有节点调用了 LLM，它就会以 `(message_chunk, metadata)` 的元组形式，将大模型刚吐出来的 Token 实时流式传输出来。
- **注意：** 即使你在节点内使用的是同步的 `model.invoke()`，LangGraph 也会在框架层将其拆为 Token 流丢给前端。
- `updates`（增量更新）—— **看流程运作**

- **效果：** 只有当某个节点运行结束时才会触发。它**只返回该节点修改或增加的 State 字段**，没变的数据不会返回。
- **数据结构：** `{ "节点名称": { "改变的State Key": "新值" } }`。
- `values`（完整快照）—— **看全局全貌**

- **效果：** 同样是节点运行结束时触发，但它会把**当前整个 State 里的所有数据**一股脑打包发给你。
- **缺点：** 如果对话历史（`messages` 列表）很长，频繁传输完整快照会非常消耗网络带宽，前端解析也更麻烦。
- `custom`（自定义流）—— **进度通知专用**

- **效果：** 它是为了解决“大模型或工具（Tool）在执行一个长达 10 秒的操作时，前端卡住不动”的问题。
- **用法：** 你可以在工具代码里通过 `get_stream_writer()` 主动发送数据（例如：`"正在读取第 2 页..."`），前端就能实时收到并展示。
- `tasks`（任务生命周期）

- **效果：** 关注的是 Graph 中节点的“管理事件”。它会明确地告诉你：`Node A 开始执行了`、`Node A 成功结束并返回了 XXX` 或者 `Node A 报错了`。
- `checkpoints`（持久化检查点）

- **效果：** 当你的 Agent 配置了内存/数据库持久化（`checkpointer`）时，每当一个步骤成功保存到数据库，就会触发此事件。这通常用于后台服务的持久化监听。
- `debug`（全量调试）

- **效果：** 相当于把 `checkpoints` + `tasks` + 所有节点的输入输出与元数据全部融合在一起输出。信息量极大，在生产环境中千万别开，但在本地写代码找不到 Bug 时它是救星。

💡 核心开发建议

1. **多模式可以组合使用：** 你的前端通常既需要打字机效果（`messages`），又需要看 Agent 正在调什么工具（`updates`）。你可以直接传入一个列表：`agent.stream(..., stream_mode=["messages", "updates"])`。
2. **推荐使用新版格式：** 如果你使用的是新版的 LangGraph，强烈建议在调用时加上 `version="v2"`，这样返回的流对象数据结构会更加统一和类型安全（带有 `type`、`data` 等标识），便于前端做多流解析
