## 他们是什么

在 LangChain 的文本切分工具箱中，**`HTMLHeaderTextSplitter`、`HTMLSectionSplitter` 和 `HTMLSemanticPreservingSplitter` 是专门针对 HTML 文档设计的“结构感知（Structure-Aware）”切分器**。

它们的核心区别在于**切分的逻辑粒度**以及**对 HTML 原生复杂元素（如表格、列表、媒体标签）的保留和转换方式**。

------

## 📊 核心区别对比

| 特性 / 维度           | 1. HTMLHeaderTextSplitter                      | 2. HTMLSectionSplitter                            | 3. HTMLSemanticPreservingSplitter              |
| --------------------- | ---------------------------------------------- | ------------------------------------------------- | ---------------------------------------------- |
| **核心切分依据**      | **标准 H1-H6 标题标签**                        | **XSLT 转换后的逻辑章节（含字体大小等视觉线索）** | **标题标签 + 语义元素（支持最大 Chunk 限制）** |
| **返回内容格式**      | 纯文本（剥离所有 HTML 标签）                   | 纯文本 / 合并相同元数据的元素文本                 | **Markdown 或保留的 HTML 元素**                |
| **对表格/列表的处理** | 直接转为扁平的文本，破坏原有结构               | 按节切分，但依然会丢失表格的行列语义              | **保持完整结构**，不会将表格或列表从中间切断   |
| **媒体/链接转换**     | 默认直接丢弃或抽离标签                         | 依赖底层 XSLT 的转换规则                          | **可将图片/音频/链接转换为 Markdown 格式**     |
| **超出大小的处理**    | 不受 `chunk_size` 严格限制，完全按标题变动切分 | 提取出 Section 后，通常需要配合字符切分器         | **内置退化机制**（超长时自动调用递归字符切分） |

------

## 🔍 深度拆解

### 1.HTMLHeaderTextSplitter：基于标题的标准切分器

- **它是怎么工作的？** 它会在文本的元素级别进行扫描，一旦遇到你指定的标题标签（如 `<h1>`, `<h2>`），就会把前面的内容切成一个块。

- **元数据注入：** 它最强大的地方在于，切出来的每一个 `Document` 块，都会在其 **Metadata** 中层层带上它所属的父级标题信息（例如：`{'Header 1': '第一章', 'Header 2': '第一节'}`）。

- **缺点：** 如果你的 HTML 页面没有规范的 `<h1>`~`<h6>` 标签（很多现代网页使用 `<span class="title">`），它就会失效，直接退化成一个大块。此外，它会洗掉所有的 HTML 标签。

### 2.HTMLSectionSplitter：基于视觉/逻辑章节的智能切分器

- **它是怎么工作的？** 它是 `HTMLHeaderTextSplitter` 的升级版，不仅看标准标题，还通过 **XSLT 转换技术** 去探测网页中的“视觉章节”。
- **特色功能：** 如果一个网页的开发者没有用 `<h1>`，而是通过调整 `<span style="font-size: 24px">` 来做标题，`HTMLSectionSplitter` 可以通过配置，智能地把这种基于字体大小的元素识别为章节边界。
- **适用场景：** 特别适合处理结构不规范的新闻、博客文章或爬虫直接抓取的杂乱网页。
### 3. HTMLSemanticPreservingSplitter：最先进的语义保留切分器

- **它是怎么工作的？** 这是目前功能最全面的 HTML 切分器。它在按照标题切分的同时，**首要任务是保护 HTML 的复杂语义不被破坏**。 

- **王牌优势（保留复杂结构）：**

  - **表格与列表保护**：如果网页中包含复杂的 `<table>` 或 `<ul>`，普通的切分器可能会在表格中间强行切断，导致 LLM 无法理解数据。它会尽量保证整个表格或列表在同一个 Chunk 里。
  - **媒体和多模态友好**：它支持将网页中的 `<a>`（超链接）、`<img>`（图片）、`<video>` 标签，直接转换为类似 Markdown 的格式（如 `[文本](链接)`、`![alt](图片地址)`），从而把多模态信息带给大模型。

  

- **大小控制：** 提供了 `max_chunk_size` 和 `chunk_overlap` 属性。如果一个章节太长，它会使用 `RecursiveCharacterTextSplitter` 进行二次切分，但在切分时依然会尽量避开表格等核心元素。

------

## 💡 选型建议

- 如果你的 HTML 结构**非常标准**（比如官方文档、导出的 HTML 报告），且只需要提取纯文本放入向量库，选择 **`HTMLHeaderTextSplitter`**。
- 如果你的 HTML 来自**各种网站爬虫**，标题标签不规范，但有明显的字体大小和样式区分，选择 **`HTMLSectionSplitter`**。
- 如果你的网页中包含**大量的表格、技术列表、重要链接或多模态图片**（比如商品详情页、财报分析、维基百科页面），且你想把这些结构完好地喂给大模型，强烈建议选择 **`HTMLSemanticPreservingSplitter`**。
